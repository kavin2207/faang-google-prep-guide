## 📌 Phase 1: Master the Core 150 DSA Problems
Stop randomly grinding 800+ LeetCode questions. Top tech interviews repeat core **patterns**, not numbers:

* **Arrays & Hashing:** Two Sum, Group Anagrams, Top K Frequent Elements, Product of Array Except Self.
* **Two Pointers & Sliding Window:** 3Sum, Container With Most Water, Best Time to Buy/Sell Stock, Longest Substring Without Repeating Characters.
* **Linked Lists & Trees:** Reverse Linked List, LRU Cache, Binary Tree Level Order Traversal, Lowest Common Ancestor.
* **Graphs & BFS/DFS:** Number of Islands, Course Schedule, Clone Graph, Word Ladder.
* **Dynamic Programming:** Climbing Stairs, Coin Change, Longest Increasing Subsequence, Word Break.

👉 **Practice Sheet:** [NeetCode 150 & Blind 75 Interactive Tracker](https://neetcode.io/practice)

## 📌 Phase 2: Master System Design (HLD & LLD)
Focus on trade-offs, scaling limits, caching strategies, and bottleneck resolution.

### 🌐 Curated High-Yield Resources (Free):
* 📚 **[System Design Primer](https://github.com/donnemartin/system-design-primer)** — The #1 open-source handbook for system design, scalability, and distributed systems.
* ⚡ **[Free System Design](https://freesystemdesign.com/)** — Comprehensive, free breakdowns of real-world production architectures.
* 🛠️ **[Devscape](https://devscape.in/)** — Curated software engineering guides, interview blueprints, and tech deep dives.
* 🎯 **[Coding Interview](https://www.codinginterview.net/)** — Practical interview preparation roadmaps and technical problem breakdowns.

### 30 High-Frequency System Design Blueprints:
1. **Design a URL Shortener** (TinyURL / Bitly) — Hashing, Base62, collisions, TTL caching.
2. **Design a Chat System** (WhatsApp / Discord) — WebSockets, long polling, delivery receipts, distributed message brokers.
3. **Design a Rate Limiter** — Token Bucket, Leaky Bucket, Redis sliding log counters.
4. **Design a Video Streaming Platform** (YouTube / Netflix) — CDN distribution, video transcoding, adaptive bitrate.
5. **Design an E-Commerce Checkout / Payment Flow** (Amazon) — Idempotency keys, distributed locking, 2-phase commits.
6. **Design a Distributed Cache** — Eviction policies (LRU/LFU), cache coherence, stampede prevention.
7. **Design a News Feed / Timeline** (Twitter/X) — Fan-out on read vs. fan-out on write tradeoffs.
8. **Design a Notification Service** — Priority queues, multi-channel dispatch (SMS, Push, Email), retry backoff.
9. **Design Web Crawler** — Politeness policies, distributed deduplication, URL frontier.
10. **Design Proximity Service / Ride Sharing** (Uber / Yelp) — Geo-hashing, QuadTrees, real-time location indexing.

## 📌 Phase 3: The Google / FAANG ATS Resume Checklist

### 1. The Google "X-Y-Z" Formula
Every bullet point on your resume must follow Google’s official rubric:
> *"Accomplished **[X]**, as measured by **[Y]**, by doing **[Z]**."*
> 
> * **Weak:** "Worked on backend APIs for order processing."
> * **Google Standard:** "Optimized order checkout latency by 42% across 1.5M monthly transactions by implementing Redis distributed caching and database read-replicas in Go."

### 2. Non-Negotiable Formatting Rules:
* **Strictly 1 Page** if you have under 5 years of experience.
* **Single-column layout** — ATS scanners choke on two-column layouts and graphical skill bars.
* **Order of sections:** `Experience ➔ Projects ➔ Technical Skills ➔ Education`.

### 3. Free ATS-Approved Tech Templates:
* 📄 **[Jake's Resume (Overleaf LaTeX Template)](https://www.overleaf.com/latex/templates/jakes-resume/syzsqbzwffcs)** — The industry-standard single-page format used by tech candidates.
